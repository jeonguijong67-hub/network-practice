# Week 5 observations

## Task 1

`/31`은 RFC 3021에 따라 두 주소 모두 사용 가능하고 브로드캐스트는 없다(`(net, net+1, None)`). 점대점 링크는 양 끝만 있으니 브로드캐스트할 상대가 없다. `/32`는 호스트 한 개라서 `(addr, addr, None)`을 돌려준다. "브로드캐스트 없음"을 `x.x.x.255` 같은 문자열이 아니라 `None`으로 표현해, 호출자가 둘을 혼동하면 바로 실패하게 했다.
`10.20.30.70`은 `10.0.0.0/8`(campus) · `10.20.0.0/16`(eng-building) · `10.20.30.0/24`(lab-floor) · `10.20.30.64/26`(lab-rack-2)의 네 항목에 들어간다. 여기에 기본 경로 `0.0.0.0/0`까지 더하면 실제로는 다섯 개가 맞는다. 최장 접두사 규칙에 따라 `/26`의 lab-rack-2가 선택된다.
같은 길이의 두 항목이 한 주소를 동시에 포함하면 두 항목은 **같은 접두사**일 수밖에 없다. 그래서 동점은 "같은 접두사에 다음 홉이 둘"인 경우뿐이고, 이는 `add()`에서 오류로 거부했다. 다음 홉까지 같으면 중복 추가는 무시한다.

## Task 2

**NAT 단수.** 캠퍼스 유선(데스크톱)은 인터페이스 주소와 외부에서 본 주소가 `163.152.219.214`로 같으므로 **NAT 0단**이다. KT 공유기 Wi-Fi(노트북)는 사설 `172.30.1.28`이 외부에서 `175.213.165.101`로 보이므로 최소 1단이다. traceroute에서 공유기(`172.30.1.254`) 다음에 `100.64/10`이나 사설 대역 없이 곧바로 KT 공인 백본(`61.78.45.77`)이 나와 **1단**으로 판단했다. 다만 2홉이 응답하지 않아 공유기 WAN 쪽을 직접 보지는 못했다.
**두 네트워크 비교.** 마스크는 둘 다 /24로 같다. 공인 주소는 인터넷을 연결해 준 쪽(고려대 `163.152/16` → KT) 블록에서 나오므로 바뀌었다. 사설 주소는 캠퍼스에는 아예 없었고(공인 주소를 단말에 직접 줌), KT에서는 공유기가 DHCP로 줬다. 두 기록은 서로 다른 기계에서 나왔으므로 수동 설정 vs DHCP 차이에는 기계 설정도 섞여 있다.
**Discover 출발 주소**는 `0.0.0.0`, 도착은 `255.255.255.255`다(패킷 2). 임대를 반납한 클라이언트에게는 쓸 주소가 없고, 서버 주소도 자기 서브넷도 모르니 limited broadcast 말고는 보낼 곳이 없다. 서버는 IP 대신 `chaddr` MAC과 xid로 답장 대상을 식별한다. 임대 시간은 3600초였다. 이 캡처에서는 Windows가 BROADCAST 플래그를 세워서 Ack까지 브로드캐스트였다. 하지만 Ack 시점의 서버는 이미 클라이언트의 MAC과 줄 주소를 알기 때문에 유니캐스트도 가능했다(자세한 내용은 `report.md`).

## Task 3

`/16`까지의 접두사는 65,536칸짜리 리스트(`addr >> 16`)에, `/17`–`/24`는 `addr >> 8`을 키로 하는 dict에 `add()` 시점에 **전개**해 두는 2단 표로 만들었다. 조회는 dict를 한 번 확인하고 없으면 리스트를 한 번 읽는다. 대가는 메모리다. 경로 5,000개가 65,536 + 13,553칸으로 불어났고, 길이 기록용 보조 배열까지 합쳐 약 2 MB다. 결과는 2,953배(`bench.txt`, 데스크톱 기준), 오답 0이다.
**R5.** 조회 비용은 이제 경로 수 N에 비례하지 않고, **단(tier) 수에 비례**한다. 여기서는 최대 2번의 조회라 상수 시간이다. N이 늘면 커지는 것은 조회 시간이 아니라 전개된 칸 수, 즉 메모리와 build 시간이다.
Python에서는 dict 한 번 조회가 C 코드 한 번 호출이지만, 비트 단위 트라이는 한 비트마다 인터프리터가 노드 객체를 따라가야 하므로 최대 32번의 느린 단계가 된다. 하드웨어는 반대다. 트라이 한 단계는 고정 폭 메모리 읽기 한 번이라 파이프라인으로 겹칠 수 있고, 최악의 경우도 주소 폭으로 정확히 제한된다. 해시는 충돌 때문에 최악 시간을 보장하기 어렵다. 사실 이 2단 표 자체가 stride 16/8짜리 multibit 트라이(라우터의 DIR-24-8과 같은 발상)다. 비트 대신 여러 비트를 한 번에 먹는 것이 하드웨어의 절충이다.
